# 日迹 Daymark

“日迹”是一个本地优先、同时适配 Obsidian 桌面端和移动端的生活打卡插件。它既能记录学习，也能记录锻炼、喝水、阅读、复盘，以及任何你想长期留下的日常。

## 功能

- 四种项目：完成型、次数型、时长型、文字型
- 自定义分类、Emoji、颜色、单位、每日目标与执行星期
- 今日打卡、日期切换与历史补打
- 时长计时器和手动增加
- 每个时长型项目显示跨日期累计投入，实时包含本次未保存的计时；撤销后累计同步回退
- 插件启用后独立运行 30 分钟休息倒计时，无任务也以钟声和弹窗提醒
- 单条撤销，不会直接删除历史文件
- 日历热力图、当前/最长连续记录、本月完成率
- 累计统计支持近 7 天、30 天、90 天与全部记录四种范围
- 汇总总投入、活跃天数、达成次数和有效记录，并以折线图显示每日投入时长变化
- 按项目类型显示累计结果：时长、数量、完成天数与文字记录数各用自己的单位
- 电脑与手机使用同一套界面和数据
- 桌面端在 Obsidian 主编辑区全页标签打开，不再挤在右侧栏
- 中文、深色模式及窄屏布局；插件在明暗宿主主题下都保持墨黑、靛蓝与深青视觉
- 背景完整复现 64 个《易经》卦象字符与 24 个 Elder Futhark 卢恩字符，以低透明度正向铺陈，不干扰操作和读屏
- 玉绿色卡片界面，区分累计投入、当日已保存时长与本次计时
- 顶栏显示本机日期与实时时钟
- “今日一爻”离线收录《周易》384爻原文与简明解释，同日同一份日迹数据固定
- 每天首次进入显示“今日签到”：呈现一则 100 字以内的《道德经》或《清静经》原文与今译；只有亲手点击“完成今日签到”才会生成同步记录
- 从长时间挂起、休眠或手机后台回到前台时自动自愈：重建计时与提醒心跳、恢复实时时钟和计时显示、补读 Vault 数据并刷新跨日状态
- 所有时长型项目共同推进循环里程碑：每累计 1 小时依文王卦序完成一卦，走完 64 卦便解锁一个高层奖励并开始新一轮
- 高层奖励依次为 Elder Futhark 24 个卢恩、古典七行星 7 个符号、黄道十二宫 12 个符号和阿拉伯—欧洲土占十六象 16 个符号
- 每个奖励显示所属体系、名称、文化象征主题、解锁轮次与累计时间；卢恩另显示字母音值和名称本义

## 为什么适合双端

实际打卡采用“不可变事件”存储：每次增加、完成、写文字或撤销，都会生成一个独立 Markdown 文件，而不是让两台设备反复覆盖同一个日记文件。每日签到同样生成独立文件。因此电脑和手机离线记录后再同步时，两边新增的内容都可以保留下来。

默认目录结构：

```text
日迹/
├─ 日迹库标识.md
├─ 项目/
│  └─ habit_xxx.md
├─ 记录/
│  └─ 2026/09/08/
│     └─ event_xxx.md
└─ 签到/
   └─ 2026/09/08/
      └─ checkin_xxx.md
```

Markdown 中既有可读摘要，也有插件维护的结构化 JSON 区块。项目文件的“项目说明”可自由编辑；事件文件建议保持不变。遇到损坏或同 ID 冲突的文件时，插件会隔离该记录并显示警告，不会静默覆盖原文件。

## 手动安装

插件尚未发布到 Obsidian 社区插件市场。解压安装包（或从源码构建），然后把以下三个文件复制到 Vault 中：

```text
<你的 Vault>/.obsidian/plugins/daymark-life-tracker/
├─ main.js
├─ manifest.json
└─ styles.css
```

回到 Obsidian：

1. 打开“设置 → 第三方插件”。
2. 关闭受限模式（如果尚未关闭）。
3. 点击刷新，启用“日迹 Daymark”。
4. 点击左侧功能区的日历勾选图标，或在命令面板运行“打开日迹”。

从旧版本升级：先停止并保存当前计时，关闭日迹插件，用新版安装包内同名三个文件覆盖此目录中的旧文件，再启用插件。不要用空目录替换整个 Vault 或“日迹”数据目录。已有 Markdown 记录和项目直接沿用，无需迁移。

## 累计统计说明

- “近 7 天 / 30 天 / 90 天”均包含今天；“全部”从第一条仍然有效的记录开始。
- “总投入”只汇总时长型项目，单位为时间；正在运行且属于所选范围的计时会实时加入显示。
- “活跃天数”表示至少有一条有效记录的日期数；“有效记录”不含撤销操作及已被撤销的原记录。
- 项目累计根据记录方式显示：时长型为总时长、次数型为数量总和、完成型为达成天数、文字型为有效文字条数。
- 趋势区只显示每日投入时长折线，不再显示柱状图或“每日完成项目数”变化；月度日历仍可用于查看和跳转到具体日期。

## 今日一爻与里程碑

- “今日一爻”只出现在当天的打卡页。首次启动 0.4.0 时，插件会在数据目录写入 `日迹库标识.md`，再用日期与该标识生成稳定索引，不使用每日随机数；因此同一份日迹数据即使在电脑和手机上的 Vault 文件夹名称不同，也会显示一致。升级后请先让这个标识文件同步到另一端，再在另一端打开新版插件。
- 插件离线内置 64 卦各 6 爻，共 384 条爻辞。古文参考[维基文库《周易》](https://zh.wikisource.org/wiki/%E6%98%93)，并以[公开结构化语料](https://github.com/muyen/decoding-iching)作机械复核；现代解释为本项目独立撰写的简明反思提示。
- 里程碑只累计“时长型”项目的有效历史时长，并实时加上当前设备尚未保存的计时。次数型、完成型和文字型项目不会被虚构为时间。
- 每累计 1 小时，当前轮便依文王卦序前进一卦；完成第 64 卦后，本轮结束并解锁一个高层奖励，下一小时从新一轮第 1 卦重新开始。
- 六十四卦网格逐格标出小时序号：本轮第 1 小时对应第 1 卦、第 64 小时对应第 64 卦，当前、完成与待进行状态分别显示。
- 高层奖励严格按体系接续：Elder Futhark 24 个卢恩 → 古典七行星 7 个符号 → 黄道十二宫 12 个符号 → 阿拉伯—欧洲土占十六象 16 个符号。每个奖励都需要完整走过一轮 64 卦。
- 当前长阶共 59 个奖励：完整走完需 59 轮、3776 小时；全部解锁后，六十四卦基础轮回仍会继续记录进度。
- 升级时会直接使用已有的有效历史累计时长计算当前位置；原先按每 64 小时解锁的卢恩门槛保持兼容，已经获得的卢恩不会倒退，也无需迁移 Markdown 记录。
- 卢恩顺序与字母音值参考 [Unicode Runic 标准说明](https://www.unicode.org/versions/Unicode16.0.0/core-spec/chapter-8/)；古典行星和黄道符号参考 [Unicode Miscellaneous Symbols](https://www.unicode.org/charts/PDF/U2600.pdf)，其历史使用可参见 [Getty 中世纪天文与占星馆藏说明](https://www.getty.edu/news/written-in-the-stars-astronomy-and-astrology-in-medieval-manuscripts/)与[大都会艺术博物馆的伊斯兰世界天文与占星资料](https://www.metmuseum.org/essays/astronomy-and-astrology-in-the-medieval-islamic-world)。
- 土占十六象采用 Unicode 17 所收录的阿拉伯—欧洲传统名称与四行单双点结构，参考 [Unicode 规范](https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-22/)和[大英图书馆 Harley MS 671 馆藏记录](https://searcharchives.bl.uk/catalog/040-002046500)。
- 所有奖励含义均作为文化象征主题和习惯激励展示，不作占卜、吉凶判断或未来预测，也不替代现实决策。

## 今日签到与抄读

- 当天尚未签到时，每台设备第一次完成插件加载会显示“今日签到”，呈现一则《道德经》或《清静经》短章。原文与今译各自都不超过 100 字，可先缓慢朗读或抄写，再开始当天的记录。
- 原文参考[中国哲学书电子化计划《道德经》](https://ctext.org/dao-de-jing/zh)与[维基文库《太上老君说常清静经注》](https://zh.wikisource.org/zh-hant/%E5%A4%AA%E4%B8%8A%E8%80%81%E5%90%9B%E8%AA%AA%E5%B8%B8%E6%B8%85%E9%9D%9C%E7%B6%93%E8%A8%BB_%28%E4%BE%AF%E5%96%84%E6%B7%B5%E8%A8%BB%29)；今译为本项目独立撰写的简明释义。
- 选择由日期与 `日迹库标识.md` 稳定确定，所以同一天、同一份 Vault 在双端会得到同一篇；“今天已经自动显示过”只记录在当前设备。若关闭窗口或按 Esc，插件当天不会再次自动打扰，可从当天页面的签到卡重新打开。
- 只有点击“完成今日签到”才算签到；关闭窗口或按 Esc 不会签到。成功后会在 `日迹/签到/YYYY/MM/DD/` 写入独立 Markdown 记录，并通过你的 Vault 同步方案在电脑和手机之间同步。
- 两台设备离线时可以在同一天分别签到；同步后两个原始文件都会保留，界面会按日期合并显示为“今日已签到”，不会重复计数。
- 朗读与抄写都是可选的；抄写框中的文字不会保存到 Vault、插件设置或签到记录。若想长期保留，请另行复制到自己的笔记中。
- 每日签到与普通项目记录相互独立，不增加达成次数、活跃天数或累计时长，也不推进六十四卦与高层奖励里程碑。

电脑和手机都需安装并启用插件。若使用 Obsidian Sync，请在同步设置中启用社区插件列表相关选项；普通的“日迹”Markdown 数据应包含在 Vault 同步范围内。

## 计时器说明

- 计时器状态只保存在当前设备，不会通过插件设置同步到另一端。
- 手机进入后台后系统可能暂停界面刷新；回到前台时插件会重建心跳并立即按开始时间恢复显示，停止时仍按实际经过时长保存。
- 时长型项目的累计投入 = 全部有效历史时长 + 当前设备尚未保存的本次计时。手动补记也计入；撤销的记录不计入。完成型、次数型和文字型没有时长数据，不显示虚构的用时。
- 休息倒计时独立于任务，没有任务也照常运行。计满 30 分钟弹窗后，倒计时与当前任务一起暂停；点击“知道了”、关闭按钮或按 Esc 后，任务自动继续，并重新开始完整的 30 分钟。休息时间不计入任务累计、统计或里程碑；有任务时仍可选择“停止并保存，去休息”。
- 提醒声音在本机通过 Web Audio 合成，不读取或下载音频文件。直接点击弹窗中的钟即可响起约 10 秒的厚重低频余韵，并浮现“清净 +1”；可切换木鱼，点击播放短促叩击音。音色记在当前设备；清净反馈不影响任务时长和里程碑。系统静音或限制播放时，弹窗仍正常出现。
- 提醒在插件层运行，切换到其他笔记或关闭日迹面板后仍生效。日迹页面始终显示独立的休息倒计时。
- 重新加载插件、重启 Obsidian、休眠或从手机后台回来时，会根据当前设备 `localStorage` 中的 `startedAt` 恢复实际计时；已经到期但尚未确认的最近一次提醒会重新出现，已确认的 30 分钟边界不会重复弹窗。
- 插件重新加载时会清理上一实例留下的失活日迹视图；若卸载前日迹处于打开状态，布局就绪后会自动建立新的主区域视图，避免继续复用“插件已经停止活动”的旧页面。
- 桌面端最小化时继续检查提醒，到时恢复 Obsidian 窗口并请求前台焦点；不永久置顶。启用期间关闭该窗口的后台计时节流，可能略增加后台耗电，卸载插件时恢复原设置。使用宿主提供的 Electron 窗口能力，受限宿主会安全降级。
- 手机锁屏、应用后台、电脑睡眠或 Obsidian 完全关闭时无法保证按时弹窗；回到前台时补一次最近到期提醒，不连续堆积弹窗。任务从实际弹窗出现时暂停，关闭时恢复；休息弹窗期间重启仍保持暂停，直到关闭恢复后的弹窗。
- 同一设备一次只能运行一个计时器；启动另一项会先保存当前计时。
- 停止并保存计时后才会写入 Markdown 事件；休息自动暂停/继续只更新本机状态。
- 当前版本将跨午夜的一段计时记在开始日期；需要时可撤销并在正确日期手动补记。
- 桌面提醒的窗口恢复及后台节流依据 [Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window) 和 [webContents](https://www.electronjs.org/docs/latest/api/web-contents) 接口；系统焦点策略仍可能限制抢占前台。

### 今日活动列表

- 点击「日常打卡」中的「今日活动」入口，或使用命令「日迹 Daymark：打开活动悬浮窗」。电脑端打开独立小窗口（初始 420×680），拖动系统标题栏移动、拖动窗口边缘缩放；右上角图钉切换置顶，偏好保存在当前设备。关闭窗口不会停止任务。
- 可从任务卡片空白处、顶部拖动柄或“＋ 活动”拖入浮窗；按钮、输入框保留原有点击与编辑行为。置顶会还原最大化浮窗，不能覆盖系统安全界面或独占全屏程序。若页签回到主窗口，重新点击“打开活动悬浮窗”即可重新弹出。
- 活动窗口可浮在普通桌面软件上方，不依赖日迹主页面；不是覆盖系统锁屏或独占全屏的系统级浮层。手机端使用独立活动页签，不提供跨 App 置顶。
- 每天自行安排，次日不会自动沿用前一天的选择；面板中切换日期可查看对应列表。「＋ 添加项目」展开选择框，平时收起。
- 拖动计时/计次模块的手柄到活动窗口，或点击模块底部的「＋ 活动」加入列表。重复添加不会出现重复行。
- 列表只关联原项目，沿用该日期生效的目标：当天已保存进度加上当前设备未保存的有效计时达标后自动打勾；休息暂停不增加进度。撤销记录导致不足目标时自动取消勾选，无需重复打卡。
- 「移除」只移除当天的列表关联，不改变原模块、目标、计时器和记录。跨午夜计时仍按原规则计入任务开始日期。
- 关联增删以独立 JSON 文件存放在 `<日迹数据目录>/活动列表`，可随 Vault 同步；正在运行的计时仍只属于当前设备，保存后另一端才会看到对应进度。

### 模块拖动排序

- 所有日常模块左上角都有拖动手柄：拖到同分类另一模块的上半部/下半部，分别放在它前面/后面。跨分类拖动会提示，不会修改分类。
- 手机可使用模块底部的上下箭头；键盘聚焦手柄后也可按上下方向键。
- 排列保存到 `<日迹数据目录>/项目顺序.json`，重启或同步后继续生效。新模块追加到所属分类末尾；不改原项目文件、目标、运行中的计时或历史数据。若另一端同时更新同一分类顺序，会提示刷新重试。

### Blender 展柜

- 打开日迹顶部的「Blender 展柜」，点击「添加渲染作品」可一次导入多张图片；支持 PNG、JPG/JPEG、WEBP、GIF、AVIF，单张最多 40 MB，不直接加载 `.blend` 或交互式 3D 模型。
- 原始图片复制到 `<日迹数据目录>/Blender展柜`，同名文件使用独立 ID，不覆盖旧作品。标题和说明保存在图片旁的 `.json` 文件；点击「编辑说明」修改，点击图片放大。
- 也可直接把图片放入该文件夹（含子目录），展柜会自动发现；没有说明文件时使用图片文件名为标题。
- 同步时需包含图片及其说明文件。展柜不上传到任何服务器，不改变任务、签到或里程碑数据；可通过 Obsidian 文件管理自行整理作品。

## 隐私

插件没有账号、服务器、遥测或网络请求。数据只写入你的 Vault；具体同步与备份由你选择的 Obsidian Sync、iCloud、Syncthing 或其他方案负责。

## 当前限制

- 不提供 Obsidian 关闭时的系统级提醒。
- 不支持跨设备接力计时。
- 项目名称、目标和计划的并发编辑可能产生同步冲突副本；插件会显示警告并合并可安全合并的规则，但不会自动删除冲突文件。
- 尚未完成 Android 与 iOS 真机发布测试，安装前建议备份 Vault。

## 数据恢复原则

记录之间始终通过稳定 ID 关联，项目改名不会切断历史。撤销是一条新事件，原始记录仍在。即使删除插件的本地设置，统计数据也能从 Vault 中的 Markdown 重建。
